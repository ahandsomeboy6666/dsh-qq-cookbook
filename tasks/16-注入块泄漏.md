# 16 注入块泄漏（prompt leakage）

## 目标

上下文里的【】注入段被模型复述时，不许发进 QQ。

## 输入

- `vendor/dsh-im-bridge/index.js`：`buildContent` / `enrichConversation` 往 `content.unshift`
  注入的十几段【…】文本；`ctx.sessionController.prompt({content})` 提交
- 注入来源模块：`tone-routing.js`（本对话近期已回复）、`life-memory.js`（角色模拟生活）、
  `wallet-awareness.js`（已查询的账户余额）、`calendar-history.js`（日历记忆）、
  `learning-memory.js`（可学习的可修正经验）
- 出站链路：`queueOutgoing` → `flushOutbox` → `scanOutgoing` → `request('send_msg')`
- 前置：无（检查是静态 + 单函数运行时，不需要 DSH / NapCat 启动）

## 输出

改三处，缺一处就是没修：

1. **注入侧**：`INTERNAL_HINT_TEXT` 常量，在 `auditForTurn` 之前统一 `content.unshift`。
   覆盖 `buildContent` / `enrichConversation` / 记忆注入全部来源。
2. **清洗侧**：`stripInternalLeak()` 重写（行扫 + `INTERNAL_TAGS` / `INTERNAL_TAILS` /
   `INTERNAL_STAMP`），并在 `flushOutbox` 里 `scanOutgoing` **之前**调用。
   剥完什么都不剩 = 这条本来只有注入内容，丢弃不发。
3. **出站侧**：`OUTBOUND_RULES` 增加三条（内部注入块 / 角色转写残留 / 内部资料 JSON）。
   strip 漏网时整条拦下，宁可不发。

配套：
- `checks/check-prompt-leak.mjs`（静态四道：约束在位、strip 有调用、规则覆盖、名单齐全）
- `checks/local/probe-strip-leak.mjs`（运行时：抠出 vendor 里的 `stripInternalLeak` 跑真实泄漏样本 + 正常回复负样本）
- `cli.mjs` 登记 `promptLeak`
- `tools/rm-anti-leak.cjs` 改为只读检查（它当初删掉了唯一的模型侧约束）

## 验收

- [x] `node --check vendor/dsh-im-bridge/index.js` → exit 0
- [x] `node checks/check-prompt-leak.mjs` → 4 PASS
- [x] `node checks/local/probe-strip-leak.mjs` → GREEN（真实泄漏样本剥成空串；7 条正常回复逐字不变）
- [x] `node tools/rm-anti-leak.cjs` → `[OK] 反复述约束在位`
- [x] `node cli.mjs check` → 含「注入块不泄漏」

> 剩下一条只能人工：在 QQ 里诱导她复述上下文，聊天窗口不出现 `【本轮` / `[日记记忆` / `nightRest`。不属于可执行验收，不占条目。

## 不做什么

- 不改注入内容本身（哪些背景该给模型，是品味问题，不是这张卡）
- 不做「拦截整条」优先于「剥掉后发」：她该说的话要留下，只删注入段
- 不动 `flushOutbox` 之外的发消息路径（`queueOutgoing` 已收敛）
- 不碰真实 QQ 账号与 NapCat 配置
