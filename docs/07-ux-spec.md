# 用户体验规格

> 本项目的唯一标准：**在 QQ 里用起来像个人，而不是像在调 API。**
>
> 技术取舍见 [ADR-007](decisions/ADR-007-streaming.md) 至 [ADR-011](decisions/ADR-011-onboarding.md)；每个指标怎么验见 [验收矩阵](04-acceptance.md)。

## 一、三条原则

1. **沉默是最大的体验问题。** 任何超过 3 秒的等待都要有可见反馈；任何失败都要有人话解释。宁多发一条「在弄了」，不让人对着手机干等。
2. **回复像聊天，不像文档。** 短句优先、主动分条、该潜水就潜水；不把 2000 字一口气砸过来。
3. **等待可打断。** 用户改主意时，一句话就能停或改方向，不用等 agent 跑完。

## 二、场景

### S1 私聊即时问答

```
用户：今天几号
  ↓ ≤300ms  桥接收到，判定为「无工具、短问题」
  ↓ ≤3s     agent 首条回复到达
用户：10 月 26 日，周一。
```

- 目标：P50 ≤ 3s，P95 ≤ 8s。
- 失败态：>5s 无回复 → 发「我还在想，稍等」；>30s → 发「这次卡住了，回「重试」我再试一次」。

### S2 私聊长任务

```
用户：帮我把昨天的报错修一下
  ↓ ≤500ms  回执：「好，我先看下。」
  ↓ 2s      工具开始（读日志）→ 进度：「在翻日志了。」
  ↓ 30s     结果 + 改动说明
```

- 目标：首个可见反馈 ≤2s；每 20s 至少一条进度（有工具活动才发，避免噪音）。
- 失败态：工具失败 → 说清哪一步失败、要不要重试。

### S3 群聊被 @

```
群友：@机器人 这个报错啥意思
  ↓ 引用该条消息回复
  ↓ ≤120 字 × 1~2 条，间隔 400~900ms
```

- 只回被 @ 的那条，不接别人的话。
- 群友之间引用第三方时，不误判成对自己说。

### S4 群聊潜水

```
群里 10 条闲聊，没 @、没关键词
  ↓ 0 条回复
  ↓ 只入库（供上下文/黑话学习），不调模型
```

- 目标：不被 @ 时不刷屏；命中关键词（可配）才接。
- 反例：每条都回、回「嗯嗯」、复读别人——都是负面体验。

### S5 发图

```
用户：[图片] 这啥
  ↓ ≤1s 回执（可选）
  ↓ 图下载 + 多模态理解
  ↓ ≤8s 回答
```

- 支持 jpg/png/gif/webp；单条多图最多 5 张；单图 ≤8MB。
- 失败态：图太大 → 「图有点大，压缩一下再发」；下载失败 → 「图没拿到，再发一次？」

### S6 发语音

```
用户：[语音 5s]
  ↓ 下载 silk → 转码 → 转写
  ↓ 文本进上下文，按文本回答
```

- 语音**入站**依赖 ASR（M2），先做「收到语音但暂时听不了」的诚实提示。
- 语音**出站**（TTS）M2，只允许语音库内文件。

### S7 打断

```
用户：算了，别弄了
  ↓ ≤2s 停止当前回合
  ↓ 「好，停了。」
```

```
用户：用中文说
  ↓ agent 跑一半 → 作为补充指令（steer），不重启任务
```

- 「停 / 算了 / 别弄了 / cancel」→ 取消。
- 其他消息 → 追加为 steer；若 agent 不支持 steer，则排队并在完成后说明。

### S8 审批

```
agent：要删除 3 个文件，允许吗？
  ↓ QQ 收到一条带选项的消息
用户：允许
  ↓ ≤1s 回填，任务继续
```

- 只认 owner；群友回复不算。
- 超时 120s → 按拒绝处理，并告知 agent。

### S9 失败与重试

| 故障 | 用户看到 | 用户能做 |
|---|---|---|
| 模型超时 | 「这次想太久了，回「重试」我再试。」 | 回「重试」 |
| DSH 断线 | 「脑子暂时连不上，30 秒后自动重试。」 | 等或回「重试」 |
| 协议端断线 | 桥接自己恢复，用户无感（超过 10 分钟才提示） | 等 |
| 限流/风控 | 「发太快了，我慢点。」 | 等 |
| 权限不足 | 「这个我干不了（没有工具权限）。」 | 换问法 |

### S10 重启与恢复

- 桥接重启：≤10s 恢复收消息；上下文不丢（DSH 会话还在）。
- DSH 重启：会话自动重建一次；用户感知为「刚才那条没成，我重发一次结果」。
- 升级 DSH：先跑探针，失败时明确说「版本 X 不兼容，停在 Y」。

### S11 管理

- `/status`：连接状态、当前模型、白名单、今日花费。
- `/cost`：本月 token 与金额。
- `/model`：切模型（会话级）。
- `/reset`：清上下文。
- `/help`：命令清单。
- 手机端也能用，不需要开电脑。

## 三、指标（可验收）

| # | 指标 | 目标 | 测量方法 | 验收命令 |
|---|---|---|---|---|
| U1 | 短问答首条延迟 | P50 ≤3s，P95 ≤8s | 桥接日志打点：收到消息 → 发出首条 | `npm run test:ux-latency` |
| U2 | 长任务首个反馈 | ≤2s | 收到消息 → 发出回执/进度 | `npm run test:ux-latency -- task` |
| U3 | 长回复分条 | >200 字分 ≥2 条，间隔 400–900ms | 日志里的发送间隔 | `npm run test:ux-split` |
| U4 | 打断响应 | ≤2s | 发「停」到 cancel 完成 | `npm run test:ux-interrupt` |
| U5 | 失败可见 | ≤5s 有人话 | 注入超时，断言 5s 内有提示 | `npm run test:ux-failure` |
| U6 | 重启恢复 | ≤10s | 杀进程重启，发消息计时 | `npm run test:ux-restart` |
| U7 | 群聊不刷屏 | 10 条闲聊 0 回复 | 回放 10 条群消息 | `npm run test:ux-quiet` |
| U8 | 配置到首条回复 | ≤15 分钟 | 新目录 + 向导，计时 | 人工验收 |
| U9 | 审批往返 | 1 条消息 | 触发审批 → 回「允许」 | `npm run test:interaction` |
| U10 | 图片理解 | 常见图能答对 | 发 3 张测试图 | `npm run test:vision` |

## 四、文案规范

- **短、具体、给下一步**。不写「系统错误」「请联系管理员」。
- 不用客服腔（「亲」「抱歉给您带来不便」）。
- 不暴露内部路径、token、堆栈；错误详情进日志。
- 中英文标点统一中文；数字与英文原样。

| 场景 | 文案 |
|---|---|
| 处理中 | 「在弄了，稍等。」 |
| 很久没动静 | 「还在跑，可能要一会儿。」 |
| 超时 | 「这次卡住了，回「重试」我再试。」 |
| 被拦 | 「这个我不方便说。」 |
| 权限不足 | 「这个我干不了（没权限）。」 |
| 需要审批 | 「要删 3 个文件，允许吗？回「允许」或「拒绝」。」 |

## 五、群聊礼仪

| 规则 | 值 |
|---|---|
| 触发 | 被 @、被引用、命中关键词、owner 前缀 |
| 单条长度 | 优先 ≤120 字；最多 400 字 |
| 每次条数 | 1–3 条；超过就合并 |
| 冷却 | 同一群 5 分钟内最多 6 条（可配） |
| 引用 | 默认引用触发消息 |
| 潜水 | 未触发时只入库，不调模型 |
| 表情 | 最多 1 个，不连发 |

## 六、明确不做

- 不做「正在输入」假状态（OneBot 无此能力，不假装）。
- 不做流式逐字（QQ 消息不能编辑，逐字会变成刷屏）。
- 不做每条消息都发「收到」。
- 不做群内主动找话题（除非显式开启仿真模式）。
- 不为了省钱牺牲首条延迟（默认 flash；复杂任务再升 pro）。
