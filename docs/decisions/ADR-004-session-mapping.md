# ADR-004：1 个 QQ 会话 = 1 个 DSH 会话

## 状态

已接受（2026-10-27，cheems 路线）。原推荐值：**按「私聊 = 一个会话」「群 = 一个会话」建立映射，持久化到 `state/sessions.json`，支持重置与退役**。

## 背景

DSH 的会话是有状态、有成本、有上下文窗口的实体。QQ 侧有两种自然粒度：每个联系人/群一个会话，或每条消息一个新会话。

后者的后果是：agent 永远不记得上一句，人格与群氛围无法积累；前者的后果是：上下文持续增长，需要压缩与退役策略。

## 决策

- 映射键：`private:<QQ号>`、`group:<群号>`。
- 值：`{ dshSessionId, preset, workspaceTitle, createdAt, lastActiveAt, permissionFingerprint, status }`。
- 生命周期：
  - 首次消息 → 建 DSH 会话（指定 preset）。
  - 后续消息 → 复用，`lastActiveAt` 更新。
  - `/reset` → 清空 DSH 上下文（新会话），映射保留键。
  - 权限/模式变化 → 标记 `stale`，下条消息重建（避免旧的高权限 preset 继续用）。
  - 长期不活跃（默认 7 天）→ 只标记，不删除文件。
- 映射文件是**用户数据**：只加字段，不删字段，不做破坏性迁移。

## 理由

- 人聊天默认有记忆；每句新会话等于把 agent 降级成单轮问答。
- 「群 = 一个会话」让群内上下文连贯，也让 token 记账能按群汇总。
- 持久化映射是重启后不串台的前提；会话 id 是 DSH 侧的唯一句柄。
- `permissionFingerprint` 解决一个真实的安全问题：改了白名单或 preset 后，旧会话仍然带着旧权限，必须强制重建。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 上下文无限增长，成本失控 | 触发 DSH 压缩；单群 token 上限告警；7 天不活跃标记 |
| 映射文件损坏导致全部重建 | 写入用「临时文件 + 原子 rename」；保留 `.bak` 一份 |
| 多人共号导致会话串台 | 映射键含账号 id；换账号时整体迁移或清空 |
| DSH 侧会话被外部删除 | 投递失败时识别「会话不存在」，自动重建一次并打日志 |

## 验证

- 单元测试：`npm test` 里的 `mapping.test.mjs` —— 建/复用/重置/退役四条路径。
- 重启测试：重启桥接后同一 QQ 号的消息仍进原 DSH 会话（断言 `dshSessionId` 不变）。
- 权限变更测试：改白名单后映射标记 `stale`，下条消息新建会话且 preset 正确。
