# ADR-010：群聊拟人策略

## 状态

待确认。推荐值：**只在被 @、被引用、命中关键词或 owner 前缀时参与；参与时短、分条、引用、有冷却**。

## 背景

群聊是体验最容易翻车的地方：回太多是刷屏，回太少是「死人」，每条都回是机器人味。参考实现区分了「聊天/仿真」两套模式，但模式切换本身对用户是负担。

QQ 群的消息量远大于私聊，逐条调模型的成本与延迟都不可接受。

## 决策

1. **触发条件**（满足任一才进 agent）：
   - 被 @（含 QQ 的 @ 与我无关的误判要排除）。
   - 被引用（引用的是机器人自己发的消息）。
   - 命中关键词表（每个群可配，默认空）。
   - owner 前缀（如「小助手」）。
2. **不触发时**：只入库（供上下文与黑话学习），**不调模型**。
3. **回复形态**：
   - 单条 ≤120 字优先，最多 400 字；1–3 条，间隔 400–900ms。
   - 默认引用触发消息。
   - 默认不用表情；用了最多 1 个。
4. **冷却**：同群 5 分钟最多 6 条；超了只回 owner。
5. **引用解析**：把「被引用人 + 原文」注入，让模型判断这句话对谁说；引用机器人自己 → 必回；引用第三方 → 不误判为对自己说。
6. **管理命令**：群里只认 owner 的 `/` 命令；其他人发 `/` 直接忽略。
7. **主动找话题**：默认关闭；仿真模式（M3）才开，且需要显式配置。

## 理由

- 「不触发不调模型」同时解决刷屏与成本两个问题。
- 短、分条、引用是真人聊天的形态，比长段落自然。
- 冷却避免被群友逗着刷屏。
- 引用解析决定「这句话是不是对我说的」，做错会出现答非所问的尴尬。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 漏回（该回没回） | 关键词可配；owner 可 `/on` 临时全接 |
| 误回（@ 别人却回） | 解析 at 段里的 QQ 号，必须等于机器人自己 |
| 群友诱导刷屏 | 冷却 + 只回 owner + 发送白名单 |
| 引用第三方误判 | 注入被引用人身份，persona 明确「只在引用自己时必回」 |
| 群里审批被伪造 | 只认 owner（见 [ADR-008](ADR-008-interrupt.md)） |

## 验证

- `npm run test:ux-quiet` → 10 条无 @ 闲聊，0 回复、0 模型调用。
- `npm run test:group-reply` → @ 一句，1–3 条、≤400 字、引用正确。
- `npm run test:quote` → 引用第三方不误回；引用机器人必回。
- 冷却：`npm run test:cooldown` → 5 分钟内第 7 条只回 owner。
