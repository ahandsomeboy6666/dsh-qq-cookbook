# ADR-006：fail-closed 安全模型

## 状态

待确认。推荐值：**默认拒绝 + 工具面裁剪 + 双侧白名单 + 发送审计 + 审批超时拒绝**。

## 背景

把 DSH 接进 QQ 等于把「一个能读写本机、执行命令、调用工具的 agent」暴露给群聊。QQ 消息是可被任何人构造的不可信输入，prompt injection 是默认假设，不是例外。

qq-bridge 的 RULES.md 已经给出成熟的分层：preset 不挂本地工具、发送强制白名单、敏感信息审计、角色由桥接注入。这些结论可直接复用，但需要写成本仓库可验收的条款。

## 决策

五条硬规则：

1. **白名单 fail-closed**：`allow.private` / `allow.groups` 为空 = 不响应任何人，不是放行所有人。黑名单优先于白名单。
2. **工具面裁剪**：QQ 会话使用专用 preset，只挂 `qq_*` 发送/查询工具与只读搜索；不挂 bash、文件读写、子代理、工作流。preset 缺失时**拒绝建会话**，绝不回退到默认 preset。
3. **发送双侧校验**：模型层（persona 规定只在明确要求时发送）+ 桥接层（目标必须命中白名单）双重校验；桥接层是硬边界。
4. **出站审计**：回复文本命中本机路径（`C:\`、`/home/`）或凭据特征（token/password/secret/api key）→ 整条拦截，换成安全提示。
5. **审批默认拒绝**：转发到 QQ 的审批请求带超时（默认 120 秒），超时按拒绝处理并告知 agent。

## 理由

- 「允许列表为空 = 全放行」是最常见的自伤默认值；反过来写，最坏情况是「没人能用」，可恢复。
- prompt injection 无法靠提示词防住，只能靠**能力裁剪**：agent 物理上没有 bash，被诱导也执行不了。
- 发送白名单必须在桥接层再校验一次，因为模型可能被诱导调用发送工具；模型层规则只是第一道。
- 审计宁可误杀（把路径当敏感信息），也不放出一条带凭据的消息。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 审计误杀正常回复（比如讨论代码路径） | 拦截时给出明确原因；管理员可临时关闭该条规则并记录 |
| 白名单配错导致「完全没反应」 | 启动日志打印生效白名单；探针输出；`/status` 可查 |
| preset 未安装导致建会话失败 | 启动时校验 preset 存在；失败信息指向安装脚本 |
| 审批转发被群友伪造 | 只接受 owner 的答复；群消息里的「通过」不算数 |
| 多实例导致绕过单实例锁 | 锁文件 + 端口探测双重检查 |

## 验证

- preset 断言：`node checks/check-preset-tools.mjs` —— 允许工具集合与预期完全相等，出现 `bash`/`write`/`subagent` 即失败。
- 白名单：`npm test` 里 `guard.test.mjs` —— 空名单拒绝、黑名单优先、越界发送被拒。
- 审计：`node checks/check-audit.mjs` —— 注入带 `C:\Users\x` 与 `sk-...` 的文本，断言被拦截。
- 审批：端到端里「拒绝」与「超时」两条都断言 agent 收到拒绝结果。
