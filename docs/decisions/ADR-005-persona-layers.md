# ADR-005：人格分两层，行为与人设分离

## 状态

待确认。推荐值：**preset 的 persona 管「怎么干活」，`roles/*.md` 管「是谁」，桥接负责注入与截断**。

## 背景

QQ 场景里有两类完全不同的提示词需求：

1. **行为协议**：什么时候说话、怎么分条、什么时候潜水、能用哪些工具、安全规则。它和桥接/工具协议强绑定，改错会导致工具调用失败。
2. **人设**：名字、性格、语气、梗、称呼。它和工具无关，用户会频繁改。

qq-bridge 的教训很直接：把工具用法写进人格卡，会在两代协议（空格分条 vs 工具分条）里必然有一代是错的，桥接只能整行过滤。

## 决策

- **preset persona**：由 DSH agent preset 提供，写行为协议与安全不变量；修改后需要新会话生效。
- **roles/*.md**：只写人设，不写工具用法；桥接每条消息前注入，`maxInjectChars` 默认 6000，超出截断。
- 注入顺序：`preset persona → role card → 本轮消息`。
- 角色卡可以按场景分小节（`## 群聊` / `## 私聊`），但小节标记只是选择器，不是协议。
- 角色卡只能由管理端修改；QQ 群里的消息永远不能改写它。

## 理由

- 两条变更频率不同的东西放在不同层，改人格不用碰代码，改协议不用碰人设。
- 注入上限是成本护栏：人格卡随每条消息发送，6000 字符约等于每次多花固定 token。
- 「只写人设」让角色卡可以跨 preset 复用，也避免把安全规则写进可编辑文件。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 用户把工具用法写进角色卡，白写还困惑 | 桥接过滤明显工具指令并在日志/控制台提示；文档写死规则 |
| 角色卡过长推高成本 | 硬上限 + 启动时警告；建议 3000–5000 字符 |
| 群友诱导 agent 改人格 | 角色卡只由管理端写；agent 无文件工具；桥接不接受群消息里的角色指令 |
| preset 与角色卡冲突（都说「你叫 X」） | preset 不写名字与语气；命名冲突由角色卡优先，preset 只写「按注入的角色卡扮演」 |

## 验证

- `node checks/check-persona.mjs`：角色卡长度 ≤ 上限、不含工具名（`qq_send_*`、`bash`、`read_file` 等）、注入后总长 ≤ 上限。
- 端到端：改 `roles/测试.md` 后下一条 QQ 消息回复带新名字，无需重启桥接。
- 成本：注入前后 token 记账差值 ≤ 上限换算值（日志可查）。
