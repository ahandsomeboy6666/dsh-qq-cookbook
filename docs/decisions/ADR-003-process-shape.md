# ADR-003：混合形态——QQ 连接独立、DSH 侧插件

## 状态

待确认。推荐值：**QQ transport 独立进程 + DSH 插件适配层，两者用 127.0.0.1 + 每次启动的随机 token 通信**。

## 背景

原结论是「全部独立进程」，理由故障隔离。调研后，纯独立进程的代价被低估了：`/api` 强制 Cookie，独立进程要自建免认证适配层；而纯插件形态又把 QQ 连接绑进 DSH 宿主。

`banana770/dsh-qq-bridge` 给出了第三种：**桥接独立进程 + `plugin-pkg` 适配层**——插件负责把本地 HTTP 翻译成进程内网关调用，QQ 连接仍在独立进程。它已在 DSH 0.2.1-rc.2 上实测。

## 决策

1. **QQ transport 独立进程**：持有 NapCat/官方 Bot 连接、消息队列、发送预算、重连。
2. **DSH 插件**：只做三件事——免认证本地路由、preset 挂载、`session/event` 订阅与交互回调。
3. 两者通过 `127.0.0.1` 上的 HTTP/SSE 通信；插件每次启动生成随机 token，写进桥接配置。
4. 单实例锁只在 transport 进程；插件可随 DSH 正常热加载。
5. 插件崩了，transport 降级到 Web `/api`（若可用）；transport 崩了，插件只报健康检查失败，不拖垮 DSH。

## 理由

- 故障隔离：QQ 侧重连、消息洪峰、协议端异常都在独立进程里，不占 DSH 宿主。
- 免 Cookie：插件在进程内，绕开 `/api` 鉴权。
- 版本适配集中：插件与 DSH 同版本发布，适配层只改插件。
- 已验证：混合形态在 0.2.1-rc.2 上跑通，不是假想。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 两个进程部署复杂 | 一键脚本同时拉起；控制台显示两者健康 |
| 插件与 transport 版本不匹配 | 握手时交换版本，不匹配拒绝并给升级命令 |
| 本地路由被滥用 | 127.0.0.1 + 随机 token + 无 CORS |
| 插件热加载导致路由短暂 404 | transport 重试 3 次 + 健康检查 |
| 用户只想要一个进程 | 提供 `--standalone` 走 Web `/api`，功能降级为无按钮审批 |

## 验证

- `npm run test:plugin-smoke` → 插件加载、健康检查、版本握手。
- `npm run test:isolation` → 杀掉 transport，DSH 仍可用；杀掉插件，transport 报健康失败并降级。
- `npm run test:standalone` → `--standalone` 模式收发正常，审批降级为文字。
- 人工：控制台同时显示「DSH 插件」「QQ 连接」两个状态灯。
