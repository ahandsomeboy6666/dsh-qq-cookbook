# ADR-009：模型路由与多模态优先级

## 状态

待确认。推荐值：**默认 flash（延迟优先），复杂任务自动升 pro；图片 M1，语音/表情 M2**。

## 背景

模型选择直接决定首条延迟与回答质量。QQ 聊天里，90% 是短问答（「今天几号」「这个字念啥」），用 pro 是浪费延迟；剩下 10% 是任务（「看下这个报错」「写个脚本」），用 flash 会答浅。

多模态是体验刚需：群里发图问「这啥」比打字常见。参考实现已支持图片入站与多模态模型。

## 决策

1. **默认路由**：
   - 私聊/群聊短文本、无图 → `flash`，推理强度 `low`。
   - 含代码块、报错堆栈、>200 字、以 `/task` 开头 → `pro`，强度 `high`。
   - 带图 → `flash`（多模态），必要时升级 `pro`。
2. **手动覆盖**：`/model` 切当前会话模型；`/model default` 恢复。
3. **多模态优先级**：
   - M1：图片入站（jpg/png/gif/webp，≤8MB，≤5 张）。
   - M2：语音入站（silk→wav→ASR）、语音出站（TTS，仅语音库文件）、表情。
   - 不做：视频、文件传输。
4. **成本**：`/cost` 可见，按会话/按天汇总；不作为路由的限制条件（体验优先），但超阈值告警。

## 理由

- flash 的首 token 延迟显著低于 pro，短问答体验差距肉眼可见。
- 「按内容特征升级」比「让用户每次选」更省心，又保留 `/model` 兜底。
- 图片是最高频多模态，先做；语音链路长（格式、ASR、TTS），放 M2 避免拖慢 M1。
- 成本可见满足「知道花了多少」，但不让省钱拖累体验。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 误升级 pro，延迟变差 | 规则保守；日志记录每次路由依据，可回放 |
| flash 答浅，用户失望 | 回答开头标注「简答」，或 `/model pro` 一键升级 |
| 多模态图片过大/格式怪 | 下载前校验字节与像素，失败给人话提示 |
| 语音 ASR 质量差 | M2 先做「收到语音但听不了」的诚实提示，再接 ASR |
| 成本失控 | 按会话限额 + 告警，不直接拒绝（体验优先） |

## 验证

- `npm run test:model-route` → 短文本走 flash、含堆栈走 pro、带图走 flash。
- [tasks/09-multimodal.md](../../tasks/09-multimodal.md)：`npm run test:vision` → 3 张测试图答对。
- `npm run test:tokens` → `/cost` 汇总与明细一致。
