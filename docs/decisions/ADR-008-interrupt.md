# ADR-008：打断、补充与并发

## 状态

已接受（2026-10-27，cheems 路线）。原推荐值：**忙时消息先做意图分类——停/改/问，分别走 cancel / steer / 排队**。

## 背景

agent 跑长任务时，用户在 QQ 上接着说话是常态：

- 「算了，别弄了」——应该立刻停。
- 「用中文」——应该作为补充指令，不该重新开始。
- 「顺便看下另一个」——可以排队。

如果全部排队，用户会觉得「它不听我说话」；如果全部取消，会误伤。参考实现的 `/reset` 只能清会话，粒度太粗。

## 决策

1. **意图分类**（轻量规则，不用模型）：
   - 停：`停`、`算了`、`别弄了`、`取消`、`cancel`、`stop` 开头 → `cancel`。
   - 改：其余消息且当前回合进行中 → `steer`（追加到当前回合）。
   - 问：当前空闲 → 正常新回合。
2. **权限**：cancel 只接受 owner；群里其他人说「停」不算，回复「这个得主人说了算」。
3. **降级**：若 Web API 没有 steer 能力（❓ 待探针），改成「排队并在当前回合结束后自动处理」，且回一句「等我弄完这个就看」。
4. **并发**：同一 QQ 会话严格串行；不同会话可并行（上限可配，默认 3）。
5. **取消语义**：cancel 后不再发送该回合剩余内容；已发出的条保留；回一句「好，停了。」

## 理由

- 打断是「被听见」的体感，比任何回复速度都重要。
- 规则分类零延迟、零成本，比让模型判断意图更快。
- owner 限定避免群友捣乱。
- 降级路径保证即使 steer 不可用也不会「消息被吞」。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 误判「停」为普通消息 | 只匹配开头 + 独立短句；不确定时按普通消息处理 |
| steer 不可用导致体验落差 | 明确回执「等我弄完这个」；M2 再补真 steer |
| 并发导致同一会话乱序 | 会话级队列，按到达顺序处理 |
| cancel 后工具残留 | 取消信号传到底；残余结果丢弃并记日志 |
| 群友反复「停」骚扰 | 非 owner 的停止请求直接忽略，不回复 |

## 验证

- [tasks/08-interrupt.md](../../tasks/08-interrupt.md)：`npm run test:ux-interrupt` → 发「停」≤2s 停止，且不再有后续消息。
- `npm run test:steer` → 「用中文」在回合中生效，不重启任务（steer 可用时）；不可用时走排队断言。
- `npm test -- queue` → 双会话并发不乱序，单会话串行。
