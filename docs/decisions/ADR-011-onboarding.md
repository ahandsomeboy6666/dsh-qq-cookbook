# ADR-011：部署、控制台与失败态

## 状态

已接受（2026-10-27，cheems 路线）。原推荐值：**向导式安装 + 本地控制台 + 统一失败文案；升级前先探针，不兼容就拒绝启动并说清原因**。

## 背景

当前部署链路是：装 Node → clone → 装依赖 → 改 config.json → 装 preset → 挂 MCP → 重启 DSH → 起桥接。任何一步错，表现都是「QQ 上没反应」，用户无从下手。

参考实现的 FAQ 有 12 条「没反应」排查项，说明这个体验债很重。UX 目标里「15 分钟到第一条回复」直接受部署影响。

## 决策

1. **一键向导**（`npm run setup`）：
   - 检测 Node / DSH / 协议端；
   - 扫码登录（协议端）；
   - 选模型与推理强度；
   - 填白名单（默认拒绝）；
   - 装 preset 与 MCP；
   - 跑自检（发一条测试消息）；
   - 失败时停在具体一步，给可执行修复命令。
2. **本地控制台**（`http://127.0.0.1:<port>`）：
   - 运行状态、连接状态；
   - 会话列表与详情（跳 DSH）；
   - 模式切换（chat / closed-agent）；
   - 人格卡编辑（保存即生效）；
   - 花费看板；
   - 日志尾随；
   - 一键重启 / 停止。
3. **失败态映射**：所有内部错误映射到 [UX 规格](../07-ux-spec.md#s9-失败与重试) 的文案表，禁止把堆栈发给用户。
4. **升级策略**：启动时跑探针；DSH 版本不兼容 → **拒绝启动**，日志与控制台显示「支持 0.2.0–0.2.1，当前 0.3.0」。
5. **幂等**：向导与控制台操作可重复执行，不产生重复配置。

## 理由

- 配置步骤数是体验的第一道门槛；向导把「12 条排查」变成「一步一提示」。
- 控制台让手机之外的场景也能管，减少「改配置要 SSH」的痛苦。
- 拒绝启动 + 明确版本区间，比「静默失效」好一万倍。
- 幂等是重复运行的前提，用户一定会重复跑。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 向导权限过大（写 ~/.dsh） | 每步展示将写什么，确认后执行；备份原文件 |
| 控制台暴露到公网 | 默认只绑 127.0.0.1 + 访问 token |
| 失败文案太笼统 | 每条文案对应一个可执行下一步（命令或检查项） |
| 升级拒绝启动太激进 | 提供 `--force` 跳过（风险自担，日志警告） |
| 幂等被破坏 | 测试 `test:setup-idempotent` |

## 验证

- 人工：新目录 → 15 分钟内收到第一条回复（[UX 规格 U8](../07-ux-spec.md#三指标可验收)）。
- `npm run test:ux-failure` → 五类故障都在 5s 内给出对应文案。
- `npm run test:setup-idempotent` → 向导跑两次，配置无重复项。
- `npm run test:version-gate` → 伪造不兼容版本，启动被拒绝且提示版本区间。
